# 工作流

## 创作主线

```
采集 → 生成 → 训练 → 剪辑/PV → 审阅 → 验收归档
```

| 阶段 | 谁做 | 产物落在哪 | 进工作台的方式 |
|---|---|---|---|
| 采集 | 采集 Agent | `1-调研与工具/`、素材库 | 设计资产库筛选服务（3950） |
| 生成 | 生图服务（ComfyUI 8190/8198 等） | 项目 `C-中间过程/` | 简易生图页（3971）、MOSS 布局（3970） |
| 训练 | 训练执行器 | 检查点与验证图 | 训练队列只读视图（`/api/training-queue`） |
| 剪辑/PV | 制作 Agent + 人工 | 工程目录 `D/G`、预览 `E` | 项目对比台的工作台组件 |
| 审阅 | 人 | 审阅页 HTML | 3900「创作与审阅」卡片（3955 自动保存） |
| 验收归档 | 人确认后系统执行 | 成品 `Z-成品/`、作品目录 | 卡片点「已审阅完成」，24 小时后转历史归档 |

## Agent 分工

- **Hermes**：日常主入口。QQ 里接话、分派、看板与工单桥接，把需要落地的活交给执行 Agent。
- **DSH 执行器**：多步实操（整理文件、跑脚本、做小工具）。每个任务一个工作目录，产物和回执落盘。
- **Codex / Claude**：工程与设计判断，关键视觉设计仍由人手动启动。
- **OpenCode**：代码与工具维护、批量整理。

分工靠工单交接，不靠上下文口头约定：上一步把文件、版本、允许修改的范围写进工单，下一步按工单接。

## 交接协议

统一工单协议见 [04-task-board.md](04-task-board.md)。要点：

1. 一个任务一个长期 `task_id`；换执行者时先保存断点并暂停，再把 `task_id` 交给新执行者。
2. 授权随工单走：谁批准的、能做多大范围、截止时间、可用资源，都记在工单上。
3. 执行中默认静默；只有三种情况主动打扰人：结果就绪、需要人做一个决定、确实完不成。

## 审阅与归档

所有需要人看的东西统一进 3900「创作与审阅」，登记后要读回卡片确认，不能只给深链接。明确完成后点「已审阅完成」，约 24 小时后转入历史归档，原页面、素材与标注都保留。

规则原文见 `policies/审阅入口与归档规则.md` 与 `policies/成果交付与最新版本查找规则.md`。
