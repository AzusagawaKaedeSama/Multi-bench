# 作品、资产与记录

| 分类 | 登记内容 | 工作台展示 |
|---|---|---|
| 已发布作品 | 用户已发布的图集、视频，关联发布凭据与实际选用版本 | 作品成果；归档后进入成果归档 |
| 作品稿 | 创作候选、审阅稿、待发布图集或视频 | 创作与审阅；历史稿独立归档 |
| 素材记录 | 新采集原件、分类、标注、精选参考、来源校验 | 素材资产库内的新增或维护记录 |
| 自研记录 | 自训模型、LoRA、工作流、提示词方法、工具、技能 | 设计资产库的自研工作记录 |
| 任务记录 | 文件整理、故障排查、运维审计、配置变更 | 任务记录与历史 |

素材资产库与自研工作各有一个长期建设入口，整体积累可以展示为建设成果。单次入库、训练或调研以记录形式列在其中。标签、账号和平台用于检索，同一文件保留主要位置与多条关联。

## 作品发布与审阅归档

- 发布状态与审阅状态分别保存。采集来源作者的发布记录归来源凭据；机主发布作品需核对所属账号、原帖、时间和对应媒体或明确确认记录。
- 完成生图、训练、标注或导出后，登记其实际类别。素材有图、自研有样图、模型有评测视频时，仍按任务用途归类。
- 需要用户选择和修改的内容可继续使用审阅页；审阅入口不改变其用途分类。
- 用户手动归档后，立即从当前卡片和指定的最新展示中移出。已完成审阅按既有24小时规则自动归档；历史页面、标注、文件与版本关系继续保留。
- 某项目最新版本已归档时，当前展示保留空位或隐藏该项目，不取更早版本重新占位。用户主动查找最新或历史时仍可检索归档记录。
- 成果归档只列已发布作品；作品稿、素材、自研和任务记录各有自己的归档范围。

## 数据库与旧登记入口

目录数据库：`E:/AgentData/ReviewHub/database/catalog.sqlite3`。它统一索引用途、版本、文件路径、审阅状态与发布关联；媒体和模型按原位置保存。

现有 `project-catalog/deliveries.json`、`catalog.json`、`publications.json` 与 `review-lifecycle.json` 作为兼容来源，按变化增量导入同一查询库。人工分类配置在 `database/catalog-policy.json`。保持原项目、文件和审阅ID稳定。

新登记通过 `project-catalog/register_delivery.py` 提交 `kind`：`draft_work`、`asset_record`、`research_record`、`operations_record` 或 `published_work`。声明发布类型后仍核对发布凭据。旧接口 `/results/<id>` 保持可用，页面按实际类别显示“作品稿、素材记录、自研记录、任务记录”。

查询接口：

- `/api/catalog?scope=active|archived|all&kind=<分类>`：分类和归档范围查询。
- `/api/catalog-summary`：两个长期建设集合、记录数量与目录规模。
- `/api/deliveries`：当前已发布作品；历史与其他记录使用分类接口。

## 备份与迁移

通过工作台导出按钮或 `node E:/AgentData/ReviewHub/catalog-store.cjs export <快照名称>` 生成一致快照。导出目录包含SQLite快照、兼容登记文件、文件位置与校验清单。

新机器先恢复兼容来源和数据库，再按清单复制原始素材、作品、模型、来源记录与人工标注。盘符变化时核对旧根目录到新根目录的映射。运行中的数据库使用一致快照导出，媒体迁移继续按文件引用与哈希核验。
