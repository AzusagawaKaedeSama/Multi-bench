# 统一工单适配协议 v1

工作台：<http://127.0.0.1:3900/#automations>。数据：`E:/AgentData/ReviewHub/database/task-board.sqlite3`。协议：`E:/AgentData/ReviewHub/task-board-protocol.json`，在线可读：<http://127.0.0.1:3900/task-board-protocol.json>。

一个任务使用一个长期工单编号 `task_id`；客户端会话使用自己的 `adapter + external_id`。同一任务换客户端时，先保存并暂停原执行，再把已有 `task_id` 交给新执行者。工单保留交接记录，旧执行后续的心跳和状态上报保持在旧执行侧，当前工单由新执行者更新。独立的训练和数据扩充分别建单，通过 `meta.source_thread` 关联监督会话。定时计划保留在原调度器，执行工单保存本次工作的要求与状态。

状态：已登记 → 排队中 → 执行中 → 待验收 → 已核销。执行阶段可转为等待资源、需要处理、已暂停；停止请求实际生效后转为已取消。只有用户验收能核销。执行者提交实际成果、完成说明或完成回执后进入待验收。

截止时间只使用用户指定的时间。训练停止、测试结束、GPU释放可分别记录；调整工单截止时间继续沿用原费用、资源和GPU授权。工作台的超时监测负责告警；资源执行器持有独立的停止守护。

## 接口与接入

| 操作 | 接口 |
|---|---|
| 登记、上报、确认指令 | `POST /api/task-board/ingest` |
| 获取工单快照 | `GET /api/task-board` |
| 实时订阅 | `GET /api/task-board/events`，SSE |
| 读取干预指令 | `GET /api/task-board/commands?adapter=名称&external_id=执行编号` |
| 工单详情 | `GET /api/task-board/jobs/工单编号` |

请求体使用 `workbench.task.v1`。必填：`schema`、`adapter`、`external_id`、`event_id`、`sequence`、`state`。`event_id` 每次唯一，重试时复用；同一执行编号的 `sequence` 递增。核心按事件编号去重，较旧序号保留原状态。已有工单传 `task_id`，同一执行编号保持原绑定。

`adapter` 使用小写英文、数字、点、横线或下划线，长度至64。新接入者可以直接使用 `dot`、`openclaw` 或其他名称。核心与页面会自动识别新名称。

Python标准库SDK：`E:/AgentData/ReviewHub/task_board_sdk.py`。接入示例：

```python
import sys
sys.path.insert(0, 'E:/AgentData/ReviewHub')
from task_board_sdk import TaskClient

task = TaskClient('openclaw', native_task_id, '本次任务名称', task_id=existing_work_order_or_none)
task.start()  # 登记并启动30秒执行心跳
task.update('running', progress={'current': 120, 'total': 300}, detail='已保存120张合格图')
for command in task.poll():
    actual_state, receipt = handle_native_command(command)  # 适配器实际保存断点、暂停或恢复
    task.acknowledge(command, actual_state, receipt)
task.finish([{'title': '成果', 'path': output_path, 'summary': '实际检查结果'}])
```

接入者根据自身接口实现 `handle_native_command`，并在工具边界或安全检查点调用 `poll`。暂停要先保存断点、停止本任务子进程，再确认 `paused`；恢复确认 `running`、`queued` 或 `waiting_resources`；停止确认 `cancelled`。工单保留提出、送达和执行确认三个时间点。SDK的心跳线程只负责存活上报，实际进度由执行阶段更新。

本机命令入口：`node E:/AgentData/ReviewHub/task-board-cli.cjs ingest`，协议对象从标准输入传入。另支持 `register`、`report`、`detail 工单编号`、`pending 工单编号`、`snapshot`。所有子进程沿用隐藏窗口与非C盘临时目录规则。

## 当前适配器

| 来源 | 自动登记依据 | 人工控制接法 |
|---|---|---|
| Hermes | 原任务数据库、真实执行心跳、工作目录状态 | 原任务评论桥接；执行方回写确认 |
| GPT / Codex Desktop | 原生轮次数据库和会话状态 | SDK或CLI领取、执行与确认 |
| Claude Desktop | 原生会话登记、状态与PID创建时间 | SDK或CLI领取、执行与确认 |
| DSH | 配置中的本机会话目录活动 | 原生插件调用相同SDK；当前旧目录已接入读取 |
| Dot、OpenClaw及后续客户端 | SDK登记或原生事件适配器 | `poll → 原生控制 → acknowledge` |

桌面观察器每10秒读取一次。Hermes每3秒同步；页面收到变更后推送。执行心跳超时180秒告警，执行中15分钟没有进度变化另行提示。观察器记录客户端实际写入时间；原生会话结束后保留“等待接续”，负责人按真实成果提交验收。接入主动上报后，主动上报的具体阶段优先于被动观察。

## 本机、手机与云端的接口边界

本机执行代理持有文件、GPU、断点与资源守护。统一工单服务保存任务要求、执行状态、干预指令和验收记录。手机Web/PWA、桌面外壳或小程序共用这套工单与成果接口；手机可以创建创作要求、审阅成果和发送调整。

云端阶段增加账号鉴权、设备身份、可靠指令收件箱和事件游标。本机通过向云端建立出站连接领取任务与回传结果，云端保留离线指令。手机发送指令后显示等待本机接收和执行者确认，完成回执绑定原工单与成果。大文件保留在素材服务，工单同步必要元数据和审阅入口。
