# 视频制作阶段门与执行纪律

> 来源：`D:\2-视频制作\260905-AI视频测试\输出\制作文档\AE制作提效与协作复盘-2026-09-06.md`（2026-09-06，31KB）。
> 本 skill 是它的可复用化版本；具体项目仍以项目自己的 `AGENTS.md` 与 `00_看这里.md`（v1 旧项目为 `00_工作台与目录规则.md`）为准。

用法：**先定"这次要过哪道门"，再动手。** 任何"完成了"的表述都必须能指回下面四态中的某一态。

---

## 1. 完成度分四态，不能用一个 `done` 混在一起

| 状态 | 能由什么证明 | 不能推导什么 |
|---|---|---|
| 工程产物完成 | 工程文件存在、结构/参数表/素材清单落盘、指纹 | 画面好看、节奏合格 |
| 技术检查完成 | 指定快照的图谱审计、音频字节核对、具体帧对比 | 全片无瑕疵、每拍都能感知 |
| 视觉/节奏验收完成 | **用户**对明确版本、范围和播放条件的审片反馈 | 以后所有改版也自动通过 |
| 输出完成 | 用户实际渲染并核对最终文件 | 本会话产出了最终电影 |

计数（层数、关键帧数、效果实例数）是**结构证据，不是审美分数**。0 表达式错误伴随 0 启用表达式，不能当成"复杂表达式系统通过压力测试"。

## 2. 九个阶段门（放行条件不满足就不进入下一阶段）

| 阶段 | 关键动作 | 放行条件 |
|---|---|---|
| 0 盘点 | 读 AGENTS/提示词/后续反馈、现有工程与未保存状态 | 当前基线、保护名单、验收状态明确；**不先清空工程** |
| 1 能力探针 | 连接 MCP、读版本/能力、用临时小合成验证必要效果 | 能读、能写、能恢复、能输出实际 PNG；"安装成功"不算 |
| 2 锁定音频与素材 | 歌词主轴、精确 PCM、人物身份、素材权限/质量 | 唯一正确音频、素材 manifest、时间换算规则 |
| 3 学习参考 | 目录→活跃合成→候选运动→具体参数→带声/图像验证 | 少量**可复现**配方，每条有出处与适用范围 |
| 4 静态设计 | 原生文字/形状/蒙版/照片，前中后景与焦点明确 | 人确认哪些视觉不可改；草图只作参考 |
| 5 动效样机 | 只做一个代表性段落，含信息期与一次真实交接 | 技术检验 + 人审；不能只演示入场冲击 |
| 6 扩展生产 | 同一 schema、预滚只加一次、共享必要慢放源 | 每段：构建→保存证据→读回→实帧检查 |
| 7 全片整合 | 出入场方向、裁切边界、Alpha、音频唯一性 | 技术抽样、帧范围、效果归零、素材/键/音频审计 |
| 8 人审迭代 | 有声实时检查，只改被指出的部分 | 按版本记录接受/待改；不是"层数够了"就结束 |
| 9 交付与 wrapup | 工程、参数、素材、指纹、状态、未验证假设 | 新会话知道先读什么、先检查什么、哪些不能重跑 |

**人审门要前置**：推荐三次实质审片 = ① 代表性静态构图 → ② **一个代表性段落的有声实时动效** → ③ 全片有声播放。
第二步不能被"代码跑完 + 几张 PNG 好像还行"替代。人暂时不能审时，继续做**未验收候选**并写明返工风险，不得事后把自动批量构建说成"用户已认可"。

反馈格式：`版本 / 主合成时间或帧号 / 希望保留的内容 / 观察到的问题 / 希望的节奏变化`——比"再高级一点"更容易变成有边界的修改。

## 3. 一次写入的固定闭环

```
执行指南 → 读当前状态/查工具 → checkpoint → 有名 Undo 事务
        → 有界写入 → 返回 ID/计数 → 另一次读回 → 实际 PNG/播放 → 决定保留
```

- 工具优先级：① 已安装 MCP 的结构化查询/预览/可复用工具 → ② 脚本新能力走 `ae_exec`，重复操作先查 Tool Library → ③ 只有界面或 API 不支持时才操作前台 → ④ **不为可选功能反复重启软件、多开渲染器或换制作栈**。
- 每次写入限定：工程路径、合成、层名/ID、预期数量。**找到 0 层或 2 层而预期 1 层时停止**，不模糊继续。
- 返回值要能复核：`{world, mapId, viewId, frames, warnings}` 比 `"DONE"` 有用。日志里的 DONE 不是画面检查。
- 新工具/新插件先用**自己命名的临时合成探针**；只清理探针自己的产物。
- 保存版本与外部索引要有提交顺序：工程失败/回滚时外部 JSON 不会自动回滚，**不能让索引先指向未确认的新工程**。

### 超时 / uncertain 不是"没做成"

- 收到 `disposition: uncertain` 后**冻结后续写入**，记录 recoveryId、scriptPath、checkpointId、当时的脚本。
- 等桥恢复、读状态，按服务端协议走恢复（`continue` 或 `restore`），明确选一个。
- **不要改个工具、换 CLI、重发相同写入来试运气**——上一次可能已经建好一半或全部。
- 只读超时也不要反复派发超慢探针；可改为先缓存数组再用原 recoveryId 继续。
- 授权/暂停/blocked/沙箱拒绝是**权限边界**，不是换通道的理由；不得自行放行安全开关。

### Windows / 界面注意

- Git Bash 每次调用是新 shell；明确 workdir，中文输出加 `PYTHONIOENCODING=utf-8`。不要依赖 PATH 上的 `bash`（可能是 WSL 启动器）。
- 前台每次动作：新截图（缩放 >0.8）→ image_scan/OCR → 动作。不猜热键、不带旧坐标连点、不擅自停止有未保存工程的软件进程。

## 4. 三层 QA 互不替代

| 层 | 查什么 | 不能替代什么 |
|---|---|---|
| 结构检查 | 可达图谱、媒体存在、父链、关键帧范围、插值、音频路径/可听性 | 画面是否好看 |
| 图像检查 | 主焦点、动作峰值前中后、每个交接、首尾、小字、裁切、Alpha；同时刻/同分辨率/同色深做前后像素对比 | 有声播放的节奏与可读性 |
| 有声动态人审 | 信息是否有时间读、每拍变化是否明显、速度对比/重心/重复度、运动质量、强效果是否喧宾夺主 | —— 这是唯一能证明节奏合格的一层 |

静态帧看不出 0.2 秒是否太短；几个 PNG 也听不出鼓点是否舒服。
预览注意：文件系统查询可能有假阴性（先让软件让出再查）；`"PNG_DONE"` 无文件证据不算通过；黑预览不等于缓存/图层错误，用最小测试逐项排除；**PNG 网格只能用于检查与沟通，不能重新导入工程冒充原生设计**。

## 5. 时间是四套坐标，必须先定合同

```text
全片帧 G = round((源时间 - S) × fps)
世界主段起帧 B；主段内部帧 L；预滚 P；包裹合成起帧 B-P
包裹合成内部帧 = L+P；回到主合成 = (B-P)+(L+P) = B+L
```

- **预滚只能转换一次。** 所有渲染帧 0 基，终点帧是排他上界。
- 素材内部还有"输入影片帧号"（如 Twixtor Frame Num）：它既不是全片帧也不是世界帧；输入帧率要读素材属性，不能统一假设。
- **音频合同**：从完整解码 PCM 按样本切片（`起始秒 × 采样率 = 起始样本`），与源 PCM 同区域逐字节比对，并核对声道/位深/采样率。
  **不要相信文件名或 seek 结果**——曾有音频文件从 35.040s 开始却叫 52.038s，能正常播放但整片时间坐标全错。
- 分镜/歌词表同时写：源秒、全片帧、世界帧、量化误差。歌词作分段主轴，鼓点只作句内辅助。

## 6. 预览与交付纪律

- 用户入口只有两处：项目根 `00_看这里.md`（第一行写当前成片）与 `Z-FinalOutput`（平铺）。标准见 `D:\2-视频制作\0-工作流\README.md`（v2，2026-10-01）。Remotion 对比台是可选工具，产物放 E。
- 只有父级能发布；**渲染成功 ≠ 通过**；失败任务不自动重试。
- 冻结交付只增不改；未通过与退回版本留在制作证据里，不替换正式交付。
- 版本/指纹/索引/审计/截图都要写明各自对应**哪一个快照**。

## 7. 收尾必须留痕

写：未验证假设、失败任务、取消的作业、服务/进程状态、下一条安全命令、以及**当时记忆中的改动 vs 当前盘上存在的文件 vs 无法归因的变化**（mtime 不是内容 diff，哈希不同也不是损坏证明）。
不要只写一句"工程已完成"。自动生成的文档要保留用户验收状态，不能每生成一次就把"未审"冲成"效果好"。

## 8. 反模式（见到就停）

- 用一个 `done` 覆盖工程/技术/人审/输出四态。
- 拿旧截图坐标点新窗口；切换工程后顺手保存；覆盖用户的 `总工程` 或参考原件。
- 多代理同时写同一个工程；把失败任务算完成；未经父级自行发布。
- 用"重装插件/换栈/换通道"解决权限或超时问题。
- 用计数、参数值、日志 DONE 代替实帧目视与用户审片。
- 为统一目录而搬迁历史工程（会断引用）。

## 9. 目录的创建与命名（v2，2026-10-01 起）

新项目用 `node 0-工作流/新项目.cjs "YYMMDD-名称" "说明"` 复制 `Z-模板文件夹`。

| 目录 | 放什么 | 谁写 |
|---|---|---|
| 根 | 只有 `AGENTS.md` + `00_看这里.md` | 父级 |
| `A-ProjectPreparation` | 前期：参考、脚本、文案、`会话.md`（用户原话） | 父级 |
| `B-SourceMateries` | 原素材 | 父级 |
| `C-MidwayMaterials` | 合同 JSON、脚本、检查帧、handoff；过程缓存进 `C\缓存\` | 父级与子代理 |
| `D-Ae&PrProjectFile` / `F-3DProject` | AE/PR 工程 / 三维工程，按 `<内容>_vNNN\` 分版本 | 子代理只写自己的版本子目录 |
| `E-AePrOutput` / `G-3DRenderOutput` | 过程导出、审片小样、checker / 三维渲染 | 同上 |
| `H-ProjectPackage` | 收集打包 | 父级 |
| `Z-FinalOutput` | 成片与定稿图，平铺，`YYMMDD_内容_vNNN.ext` | **只有父级**，验收实帧后放入 |

**四条硬规则**

1. 根目录一份说明：`00_看这里.md` 第一行 = 「当前成片：`Z-FinalOutput/…`」。
2. Z 只放结果、平铺；多文件版本才建一层 `vNNN_内容\`；审片过程进 E。
3. 用户要看的文件离项目根 ≤ 2 层；chrome profile、node_modules、抽帧等进 `C\缓存\`。
4. 只用这 9 个字母目录；禁止同义目录（`最终/`、`修正/`、`new/`、`备份/`、`old/`、`E-ExportedVideos`）；新增类别先写进项目 `AGENTS.md`。

历史项目（含 v1 结构的 2609xx 项目）原样保留，入口为各自 `00_工作台与目录规则.md` 顶部的「成片看这里」。
