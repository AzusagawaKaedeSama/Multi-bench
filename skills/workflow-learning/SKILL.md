# 历史检索与流程改进

> 更新：Codex（GPT-6）· 2026-10-28

## 先看已有能力与实际调用

用户要固定流程或查询已有skill/workflow时，先运行 `scripts/catalog.py`：按真实源文件合并入口，列触发描述、路径、同名分歧与缺失入口。需要更新静态目录时将 `--output` 指向非C盘长期记录位置；查单项用 `--query`。扫描有20秒与条目上限，结果带范围和截断状态。

把每条候选写成：**什么请求会用到 → 输入 → 决策与执行入口 → 输出 → 如何验收**。同时核对源会话、当前脚本和实际成果。优先补原技能；重复命令写脚本，可变参数留给当前任务选择；长期偏好按原共识流程维护。来源材料保持只读。

判断Agent工作质量时，先读用户对该版本的审阅、选择、评分与具体意见，再看自动检查与执行记录。用户审阅为不可用的流程保留为失败案例或待修复基线；已有效的局部接口单独列出。用户在2026-10-28明确补充此要求：SVFI v0012的人工审阅为3/25条可用，尽管原Agent曾报告多数通过机器检查。新评分默认5档，需要更细区分时用10分；原评分量表、题目、图片/视频版本与原话均保留。

值得固化的内容至少解决一个已发生的重复操作或错误，并能指到真实输入、运行入口及结果。按 [复用判据](references/reuse-contract.md) 验证。2026-10-28首批已接入：`svfi-jianying-preedit`（H3去重、帧率预算、剪映草稿）、`creative-resource-router`（现有标签/LoRA/提示词/配方统一查询）、`three-d-pv-pipeline`（冲破穹顶运镜案例）。

历史命中记录 `E:/Hermes/shared/experience/usage.jsonl` 用于观察检索覆盖；执行效果另记 `scripts/record_reuse.py`，记录源任务、本次任务、实际产物、验证方法和观察结果。隔离演练记 `offline_checked`，在另一个真实任务采用并完成验证后记 `task_verified`。本轮自测和外部任务复用分别统计。

复盘优先交出一个可调用的改动或一条有证据的候选。普通日常总结保留安静记录；告知用户时先给新增能力、验证结果或需要决策的事项。按历史原授权推进技术整理与验证，用户长期偏好和新增付费等沿对应授权处理。

## 使用历史

软链接提供文件入口；检索遵循“索引→关键词→相关片段→核当前状态”。先读 `D:/1-个人agent/共享记忆/索引.md` 与 `会话索引.md`，有准确会话入口则直接用它。跨客户端读取器：

```powershell
& 'D:/anaconda3/python.exe' 'D:/1-个人agent/共享记忆/scripts/history_reader.py' search '本次关键词' --source all --limit 5 --file-limit 30 --max-chars 5000
```

读取器默认限时20秒；继续读取单个相关会话也限制字符。Hermes群/私聊历史优先用原生会话搜索，指定相关profile和关键词。共享历史、记忆原文及数据库保持只读。只给执行者本阶段所需的结论与成果路径，原文留在来源，不把整段聊天复制进新任务。

小红书/B站任务无须等用户说“上次”，每次执行前加载 `reference-collection-windows`，查相关成功入口。记录中的端口、路径、登录状态、模型和计费规则需结合当前状态复核。

## 一次轻量复盘

在本轮任务完成、失败或用户纠正后，先用现有成果、错误和用户反馈判断是否有可复用的新经验。普通闲聊、只有状态查询、没有变化的成功步骤不额外调用模型。确有材料时，创建标题为 `流程复盘：阶段名称` 的工作卡，固定用 Qwen Flash；同一会话同一阶段每天只预约一次，全体Agent每天最多五次，由共享计数程序限制。预约后创建失败也占用一次，不改名绕过，不对复盘任务再次复盘。

一次只看本阶段摘要与最多两个证据片段，输入目标不超过6000 Token、输出不超过1200 Token，计入任务预算。Token与金额仍按目标控制；复盘预约次数已由程序限制。达到次数上限时保存现有候选与证据，继续当前交付。

复盘记录：触发问题、实际原因、已验证办法、适用条件、失败边界、来源指针、复测方法。优先补现有技能；重复事件合并到同一案例。只有猜测的修复先记候选，不写成默认成功流程。用户直接确认的纠正可以立即更新，并保留来源和日期。

## 行迹与共识（2026-10-18 起，用户定名）

对齐行迹、普及新知、凝聚共识、复盘迭代。目录 `E:/Hermes/shared/experience/`，插件 experience-base 每轮自动注入，不必手动加载。

- 行迹：工作完成、失败或被用户纠正时当轮写进 `行迹/`，带作者与来源，末尾留「## 新知」段。
- 对齐：把行迹用文字交给用户看（群里直接说，不发文件）；用户的回复原样记入「新知」并注明日期。
- 共识：用户确认后由 Doloris 编号并移入 `共识/`；与常驻共识冲突的退回，重复的合并，过时的移入 `已退役/`。常驻共识只记录用户直接指定的长期要求，改动须用户确认。
- 复盘：`行迹/待复盘清单.json` 列着未经用户审看的历史资料，按优先级拆成行迹交用户对齐；`usage.jsonl` 用来找常用和从未命中的条目。需要多步流程的才另写成技能。

## 更新技能

执行者在自己任务目录提交候选与验证证据；Doloris统一检查冲突、备份并发布到 `E:/Hermes/shared/skills`，避免多位Agent同时改同一份正文。使用原生技能管理工具；修改前备份并保留差异。SKILL.md只放触发条件和关键步骤，长命令、截图与细节放相关references，按需读取。新增技能应解决具体重复问题，不把一次例外扩大为所有任务的硬规则。共享技能发布前检查与现有记忆/技能的冲突，并进行一次只读或隔离验证；需要真实付费、发布或其他额外权限的验证沿用用户授权范围。

技能共享仅保存脱敏技术流程。私聊原文、账号信息、凭据、个人细节保留在原有私有来源；在群里只报告任务所需的通用结论。不要把私聊全文做成共享技能。
