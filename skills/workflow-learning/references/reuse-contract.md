# 判断一条技能是否省事

**技能负责让Agent作出更好的具体决定，并找到已有执行入口。** 工作流保留参数、操作顺序和输入输出，脚本承担重复且确定的计算；会话行迹保留来源与当时的结果。

一条技能交付前核对五件事：

1. 自然请求能触发，描述覆盖真实使用场景；普通无关请求继续使用原流程。
2. 有能访问的资源和实际入口，关键参数可由本次输入确定。源码、模型、标签、配方分开放在原位置，技能负责查找和组合。
3. 包含影响结果的关键决定。例如补帧先查重复帧、按变速最小导数预算；选LoRA先查底模与原图；回望把行进方向与视线分开。
4. 输出能用于下一步，验收看对应实物。保存草稿看草稿内容与实际打开；验证运动看连续帧和带声片段；提示词配置看引用与模型兼容性。
5. 能在另一个实际任务调用，并记录结果。按原始事实记录减少了哪些补充提示、返工或人工操作；缺少前后对照时记录观察到的结果和待验证项。

**创作质量首先看人类实际审阅和选择。** 将采用、弃用、修改意见关联到对应原件SHA256、版本、评分题目与量表。机器检查结果单独记录；出现分歧时按人工反馈定位缺陷、降级当前推荐状态，再验证。新评分按5档或10分设计，默认5档；保持旧分值和尺度原样。

## 晋升与合并

- **候选**：有重复价值与来源，还在核参数/环境。
- **已接入**：技能描述、共享入口、依赖和脚本已读回。
- **隔离验证通过**：离线或小样验证通过，带产物与验证方法。
- **实际任务复用通过**：不同任务使用成功，有输入、输出与验收依据。
- **人工认可**：用户对具体版本反馈认可，按其反馈原样记录。

一个流程通常由已有技能加一个参考案例或一个脚本完善。新建技能用于独立的触发场景；旧入口修好时合并重复副本。过去规则涉及用户偏好时按原确认流程维护；技术实现已在当前授权内则直接修复。

## 下一次执行的最小记录

`source_task`、`current_task`、`skill`、`status`、`artifacts(path/sha256)`、`validation`、`observed_result`。人工补充提示次数、返工次数、操作耗时可在真实计量时附 `metrics`，每项注明观察来源。仅记录必要任务证据，原会话与凭据保留在原处。

每日摘要保持已有采集职责。阶段复盘先查询技能目录及复用账本，补充实际变化；周回顾按“修复入口、接入能力、真实复用结果、仍需验证”组织，重复关键词作为候选线索。调度与付费模型配置随用户另行交办更新。
